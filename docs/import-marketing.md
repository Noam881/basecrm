# Marketing original-field and canonical imports

Marketing owns acquisition, consent and qualification originals and canonical attribution. Core Documents/Activity, Core's hidden attribution column and frozen `AttributionSnapshot` are not import destinations. No new table or business key is introduced.

`Imports\Sources` has no default policy or HTTP registration. Reviewed server code supplies a `SourcePolicy` for an exact provider/native-parent role, authorizes scope/internal references, declares all Marketing source column IDs and converts only reviewed fields. Authorize this policy before source fetching. No Monday provider or source adapter is activated by this capability.

`Originals::preserve()` appends immutable `marketing_history` occurrences with kind `source-lead` or `source-company` and the actual native parent ID. The approved internal Company holds internal references without a fake Lead/profile. Genuine headers, types, exact raw JSON strings, availability, original author/time and source revision remain in Marketing. History's normal actor/time describe the actual importer. Object-key ordering is canonicalized for keyed receipts; original strings and list order are untouched. Every new revision has a verified predecessor, unchanged content reuses its revision, and business data plus its actual readback receipt commit atomically. Metadata errors never return the raw payload.

`AttributionImporter::apply()` reads a verified original, not caller-supplied field values. The owning converter returns `available` plus a typed scalar/null for existing `LeadFields` keys. Unknown consent is unavailable or genuinely unknown, never truthy opt-in or inferred refusal. Only requested, validated deltas are merged through `Attributions`; the existing 23-key schema supports the 18 reviewed source mappings without duplicating fields. The five unmapped keys and linked CRM campaign are left untouched. Original preservation may succeed while canonical fields remain unresolved.

Per-field keyed Ledger receipts and `FieldConflict` protect CRM edits, distinguish unchanged source from target changes and verify actual destination values. JSONB siblings and unsupported legacy scalar types are not decoded through floats. Non-object legacy containers are not overwritten. Lead automation holds acquire their advisory lock before any import Lead row lock, matching native import lock order. All requested fields retain an observed keyed hash; applied fields must match their expected hash and skipped/replayed fields must retain their observed value. The importer rechecks these values after all receipt and authorization callbacks, rolling the write and receipts back together on late changes. Every call checks a fresh verified active actor, module enablement, import and Marketing permissions, current native access, runtime boundary and open batch. Caller target IDs, fingerprints and ownership registrations are not accepted.

Read routes under `/marketing/{leads|companies}/{id}/originals` use current Marketing view permission plus native Lead/Company access, verify retained receipts and expose paginated author/time and verified source board/item metadata followed by explicitly selected original content. The Lead attribution panel and Company identity contribution render escaped text with shared Material primitives and English/Hebrew labels. There is no HTML rendering or automatic URL following. Module disablement blocks both UI and forced requests. Existing general attribution audit history and frozen extraction snapshots remain unchanged.

Source extraction, reviewed identity matching, provider registration, actual files, source update/reply bodies and production imports remain separate reviewed operations. Keep conflicting parties separate under the approved source-ID policy; review flags retain that decision. Never place credential or financial source rows into this Marketing history.
