# Neutral Material Design 3

The shared CRM follows Material Design 3 conventions with an exclusively achromatic palette. Alpha and Beta retain separate identities, terminology and optional modules while using charcoal/grey primary tones. No green, purple or chromatic status/error accents are part of this theme. Administrator settings offer neutral tones; server validation rejects non-grey RGB values.

The shared primitives live in `packages/awove/crm-core/resources/css/components.css`; shell/layout tokens live in `core.css` and table structure in `table.css`. It defines Material color roles for surface containers, on-surface, primary, secondary, outline and their corresponding foregrounds; the standard 4/8/12/16/28/full corner scale; Roboto type styles; a 4px spacing grid; and 150ms state transitions and 250ms drawer/rail motion with reduced-motion support.

Shared controls use 40px filled/outlined pill buttons (48px on compact touch layouts), 56px outlined text/select fields with floating labels, 32px chips, 56px drawer destinations, a collapsible desktop drawer and 80px icon rail, a modal mobile drawer, 12px outlined cards, neutral selected containers, visible focus indicators and explicit error text. Login/account security controls use the same typography, neutral palette and button geometry. Navigation uses locally bundled Material Symbols; fonts require no external font service.

The main canvas contains the current page title and working content. Profile/name, account actions and navigation live in the sidebar; decorative eyebrows, page slogans and a separate app header are omitted. The desktop rail preference is remembered per browser origin/user; mobile navigation closes on selection, Escape or backdrop click and uses native dialog focus containment.

Official `@material/web` ripple components supply hover/pressed state layers on native semantic controls and Inertia links. The integration reattaches after Vue updates and keeps ripple bounds positioned on each control. Native form behavior, keyboard access and existing server permissions remain in place. This is a Vue implementation of Material 3 using official Material Web interaction primitives; it does not replace Laravel/Inertia with an unrelated UI application.

References: [Material 3 typography](https://m3.material.io/styles/typography/type-scale-tokens), [navigation drawer](https://m3.material.io/components/navigation-drawer/specs), [Material Web ripple](https://github.com/material-components/material-web/blob/main/docs/components/ripple.md), [official Material 3 type and shape scales](https://developer.android.com/develop/ui/compose/designsystems/material3).

Verification: Vue/TypeScript, production frontend build, formatting, PHPStan, PostgreSQL backend tests and desktop/mobile CRM/extension browser scenarios. Navigation examples: [desktop rail](screenshots/desktop-collapsed-navigation.png), [mobile canvas](screenshots/mobile-navigation-canvas.png), and [mobile drawer](screenshots/mobile-navigation-drawer.png). Visual inspection corrected a missing icon-font family and a ripple-containment issue before publication. The earlier container-image smoke in `checkpoint-1.md` predates this theme; no new container runtime acceptance is claimed for this visual iteration.

## Shared controls and spacing

`components.css` is the single definition for buttons, text fields, select fields, labels, card surfaces, forms and action rows. Host Button/Input/Label components delegate to these classes; authentication, account settings, core pages, optional modules and table dialogs share them. Compact dialogs override field tokens rather than duplicating geometry. Range, hidden and OTP controls are excluded from text-field geometry.

Use `crm-form` for a stacked form (24px gap), `crm-form-grid` for a responsive two-column form, `crm-field` for label/control/help (8px gap), and `crm-form-action` for wrapped action rows (12px gap). Use `crm-flow` for spaced card content and `crm-card` for the common surface. Direct submit buttons align to the start by default; intentional full-width actions retain that modifier. No per-page button margins are needed. These conventions also apply to future modules and screens; see `AGENTS.md`.

Lead tables put contact and company names first. The enquiry title is optional and hidden from the default layout; it remains available through Columns. Demo people use Jewish/Hebrew names written in English, such as Noa Levi, Daniel Cohen and Yael Mizrahi, with fictional contact details and company names including Rimon Studio, Carmel Supply and Shaked & Co.
