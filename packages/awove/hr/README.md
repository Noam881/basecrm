# Human Resources (M03)

Optional `awove/hr` 1.0.0 requires `awove/crm-core ^1.1`. Enable `hr` explicitly. It works with Sales, Finance, Assets and recruitment integrations absent. The shared employee-reference capability is core: an employee does not need a contact or login account. Existing people are selected explicitly; names are never an automatic merge key.

HR owns private employment profiles, vacancies/candidates, onboarding/offboarding cases, document references and case history. Private employee/candidate email, phone, notes, role descriptions, responsibilities, managers, dates and final-pay information are not inserted into shared contacts or core employee references. Shared references contain only a stable identity/name/active flag plus separately authorized optional links. HR profiles have one stable employee reference each; inactive references and historical assignments remain readable within their authorized scope.

Employment profiles record role, role description, responsibilities, a manager employee reference, start date, employment status, private contact details and responsible HR staff. Active/Inactive are minimal employment-status defaults. Shared-reference eligibility is changed separately and explicitly; changing a private status does not disable a login. Vacancies record role, description, hiring owner, opening date and minimal Open/Closed state. Display labels can be configured through `hr_employment_statuses`, `hr_vacancy_statuses`, `hr_candidate_stages` and `hr_checklist_statuses`; stable IDs are unchanged and installation never overwrites these labels. Candidates retain their vacancy, private contact information, CV/document references, notes, next action and source stages New, Screening, Interview, Offer, Hired, Rejected. Marking Hired does not create an employee or login; an employee reference can be resolved explicitly. A vacancy that later becomes inaccessible is redacted while its relationship is preserved on unrelated edits.

Cases retain employee, onboarding/offboarding purpose, name, owner, due date, manual completion date and offboarding final working date. Checklist items use the existing core work-item entity through typed `hr_case_items` relations. Categories cover documents, access, equipment, introductory training, handover and final-pay transfer. Statuses are Not started, In progress, Done and Skipped. Skipped is a terminal state without a completion date and is allowed only for optional work. Completing a case requires at least one recorded checklist item, all required work Done and optional work Done or explicitly Skipped. It records the chosen date and preserves all task history. There is no recurring-task generator or automatic account provisioning, access revocation, equipment return, payroll transfer or pay calculation.

Abandoning a case uses archive: the parent and every linked task are archived in one versioned transaction, preserving incomplete statuses and history. If the actor cannot archive assigned work, a validation message requires an appropriately authorized HR manager. Archival never marks work Done. Offboarding may explicitly retain the shared employee reference as inactive with `employees.references.manage` and the current employee version; the linked login is unchanged.

Permissions are independent and never automatically granted: `hr.employment.*`, `hr.recruitment.*`, `hr.cases.*` each define view own/all, create, edit own/all, assign, archive and export. New assignment requires an active staff member who already has the relevant scope. Unchanged inactive owners remain historical references. Shared employee selectors require `employees.references.view`; shared-reference edits need `employees.references.manage`. Private HR documents additionally need `hr.documents.view`; adding/archiving links needs `.manage` and parent edit access. Final-pay information needs `hr.final-pay.view`; edits also need `.edit`. Unauthorized document/final-pay data and hidden relation IDs are removed from DTOs, table schemas, search and exports. Checklist assignees may work on their own items while restricted parent identities remain redacted.

CVs and HR documents currently use supported HTTPS document links, not binary file upload. Parent authorization and the document-view grant are rechecked on every redirect; raw links are omitted from profile DTOs and every CSV. References are retained: add a replacement and archive the old reference rather than overwriting it. The external document provider controls the underlying document's access. No synchronization or external account connection is performed.

`/hr` provides scoped advanced tables, search, columns, saved views, multi-sort/filter, owner/period filters, pending-case views and overview contributions. Periods use employee start, vacancy opening, candidate next action and case due dates. Date-only decisions use the installation timezone; timestamp presentation uses display preferences. Only permitted sections/counters appear. Candidate follow-ups, open-case due dates and shared checklist work use fresh, deduplicated owner reminders; completion, terminal stage, archive, permission loss or module disablement removes obsolete previews. Disabling preserves records and denies endpoints, document redirects, export, contributions and background delivery.

CSV exports preserve applied overview filters and complete table state, enforce a 5,000-row preflight limit and use shared formula-injection defense. Candidate/employee exports require their own explicit export grant. CV URLs, private interview notes and manual final-pay content are omitted. No HR CSV import is introduced.

Verification: `tests/Feature/HrTest.php` covers private data boundaries, non-login employees, versions/fresh actors, ownership, explicit recruitment stages/identity resolution, hidden relations, document grants, shared checklist tasks, required/optional states, manual completion, offboarding/inactive retention without login revocation, abandoned cases, final-pay isolation, scoped CSV and stale/disabled reminders. `tests/e2e/hr.spec.ts` covers actual desktop/mobile create/save/reload on an HR-only local installation at `127.0.0.1:8099`, with guarded reserved accounts and private fixture recovery snapshots.

Deferred by source: shifts, attendance, leave approvals, payroll calculation, performance reviews and applicant sourcing integrations.
