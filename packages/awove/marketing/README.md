# Marketing module

Optional `awove/marketing` 1.0.0, Core contract 1, Core ^1.1. Enable `marketing` in the installation manifest. Campaign planning, manually reported performance and content planning run without Sales or Finance. The optional opportunity attribution panel requires both Sales and Marketing. No live ad integration, publishing, automation, accounting, attribution model or AI is included.

Campaigns retain objective, channel, responsible owner, start/end, planned budget and currency, materials/landing links, and Planned/Active/Completed/Paused states. Content retains channel, format, owner, planned and actual publication dates, draft/asset/publication links and Idea/Draft/Ready/Published states. Published requires a date and HTTPS publication link; changing state is a manual record, never a publishing action. Known status display labels may be overridden under `marketing_campaigns_statuses` and `marketing_content_statuses` without changing stable keys. The module label uses `module_labels.marketing`.

Campaign/content permissions are explicit: `marketing.{campaigns,content}.{view.own,view.all,create,edit.own,edit.all,assign,archive,export}`. Performance inherits its parent campaign's current scope/edit authorization. New permissions are not automatically granted to Employee roles. All reads and writes reload the active actor, guard module enablement, and enforce current owner scope. Records use optimistic versions and transactional locks. Changed assignments require assign permission; unchanged inactive or unassigned ownership is retained. Archive retains data/history and makes the record read only. Performance from archived campaigns remains part of historical reporting. There is no destructive delete.

Actual spend and reported leads are manually entered for inclusive reporting periods. A locked parent campaign serializes every report insert/correction; no two periods in that campaign may overlap, including boundary dates. Adjacent dates are allowed. Corrections append history; a stale version gets HTTP 409. Planned budget is separate from actual spend. Amounts are exact decimal strings with two decimal places; floats, negative values, exponents and excess precision are rejected. A zero lead denominator yields no CPL. Aggregate CPL is total spend divided by total reported leads, rounded half-up once to 2 places; spend from zero-lead rows stays in the numerator. Filter dates include whole reporting periods only (`start >= from`, `end <= through`); no proration. Reported leads never include or combine with authorized linked CRM opportunity counts. Currency snapshots and the shared Core Currency registry block monetary changes/combined totals on configuration mismatch while retaining readable rows and their original currency labels.

`marketing.campaigns`, `marketing.reports` and `marketing.content` use the shared advanced DataTable: per-user column layouts/reordering, all permitted fields, sorting, filters, search, density and saved views. CSV exports use the identical scoped current filters/search and formula-safe Core Csv (maximum 5,000 rows). CSV import is not implemented. Due content uses shared WorkReminders with fresh module/recipient/owner/record-version checks at queue delivery and listing; publication, archive, reassignment, revocation and disablement suppress stale previews/work. Document endpoints authorize the current parent before Core DocumentLinks emits a private no-store/no-referrer HTTPS redirect; no server fetch or public storage is introduced.

## Legacy attribution extraction

Migration 001100 creates module tables. Additive migration 001110 uses PostgreSQL `INSERT ... SELECT` to copy the existing JSONB value without PHP normalization, string casts, ID conversions or name matching. An immutable `marketing_attribution_snapshots` row stores the original lead ID, raw JSON, original version and created/updated timestamps. The original `crm_leads.attribution` column is frozen, retained and hidden from all shared Lead DTOs; shared Lead mutations reject the old attribute entirely. Existing lead IDs, timestamps, versions and stage/history rows remain unchanged. An idempotent rerun never overwrites snapshots or subsequent module edits. SQL null stays absent; JSON null, arrays, nested unknown values and typed external IDs are retained exactly. Historical Core activity is retained.

Canonical module payload is separate from nullable `linked_campaign_id`, a real CRM campaign link. Legacy `campaign_id` remains the original external field and is never converted or implicitly matched. Attribution has no duplicate independent owner: permissions `marketing.attribution.view/edit` are combined with fresh shared Lead view/update policies. Marketing disablement, Sales disablement or lost Lead access denies endpoints and removes table/panel contributions. Linked campaign names/IDs are independently scoped, and hidden historical links survive an ordinary save or redacted null. Replacing a hidden link is denied. Existing `attribution:*` column IDs are unchanged, and dormant saved layouts survive disable/re-enable. The panel submits only changed fields, retaining unknown or non-string legacy values during unrelated edits. Generic lead/contact source remains a shared Core/Sales field.

Tests: `tests/Feature/MarketingTest.php`, shared legacy boundary regressions in LeadWorkflowBasicsTest, strict local `scripts/marketing-browser-fixtures.php` and desktop/mobile `tests/e2e/marketing.spec.ts`. Browser proof uses only isolated Alpha reserved `example.test` accounts, protected ownership checks, private recovery snapshots and before/after cleanup. Never run these fixtures against live data.
